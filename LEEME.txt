PROYECTO WEB-OEA
================

Este proyecto tiene dos partes:

Frontend-OEA/
  El sitio web (HTML, CSS, JS). Se abre poniéndolo en htdocs de XAMPP y
  accediendo por http://localhost/Web-OEA/Frontend-OEA/ (nunca con doble
  clic al archivo).

Backend-OEA/
  La API (NestJS + Prisma) que conecta el formulario de Matriculación y
  la sección de Eventos a una base de datos real en Supabase. Instrucciones
  completas de instalación y despliegue en Backend-OEA/README.md.

Mientras el backend no esté desplegado, el sitio sigue funcionando con
el archivo manual Frontend-OEA/data/eventos.json para Eventos, y el
formulario de Matriculación mostrará un mensaje pidiendo usar WhatsApp
o correo si el backend todavía no responde.

5. PROBAR EL FRONTEND
---------------------

No abrir los HTML con doble clic, porque el navegador puede bloquear la carga
de archivos JSON y algunas funciones. Usar un servidor local.

Desde la carpeta Web-OEA:

  cd Frontend-OEA
  python -m http.server 8080

Abrir:

  http://localhost:8080/index.html
  http://localhost:8080/blog.html
  http://localhost:8080/matriculacion.html
  http://localhost:8080/contactos.html

Revisar menú móvil, enlaces, imágenes, formulario, mapa y diseño en teléfono
y computadora.


6. CONFIGURAR Y PROBAR EL BACKEND
---------------------------------

Abrir una terminal en Backend-OEA y crear un archivo .env con las variables
de Supabase. No copiar contraseñas dentro de este documento ni subir .env a
GitHub. El archivo .env ya está excluido por .gitignore.

Comandos:

  npm install
  npx prisma generate
  npx prisma migrate dev --name init
  npm run seed
  npm run build
  npm run start:dev

El seed debe dejar exactamente 3 eventos de ejemplo. Si se ejecuta varias
veces, no debe crear duplicados.

Probar en otra terminal:

  GET  http://localhost:3000/events
  POST http://localhost:3000/matriculas

El POST de prueba debe usar estos datos:

  nombreEstudiante: Prueba Test
  nivel: BACHILLERATO
  jornada: VESPERTINA
  nombreRepresentante: Representante Test
  telefonoRepresentante: 0999999999

La respuesta esperada del POST es HTTP 201 y un registro con estado
PENDIENTE.


7. SEGURIDAD
------------

Antes de producción:

  - Cambiar la contraseña de Supabase si alguna vez fue compartida.
  - Nunca subir .env a GitHub.
  - Configurar ADMIN_API_KEY en el entorno del backend.
  - Mantener protegidos GET /matriculas y GET /matriculas/:id.
  - Usar el header x-admin-key para consultas administrativas.
  - Mantener POST /matriculas público para el formulario del sitio.
  - Usar HTTPS en el despliegue.
  - Configurar CORS solo con el dominio real del sitio publicado.


8. CONECTAR EL FRONTEND CON EL BACKEND
---------------------------------------

Mientras el backend no esté publicado:

  - Eventos usa Frontend-OEA/data/eventos.json.
  - Matrículas intenta usar http://localhost:3000/matriculas.

Cuando exista una URL pública, actualizar en:

  Frontend-OEA/js/main.js

Cambiar EVENTOS_CONFIG.apiUrl al endpoint público /events y
MATRICULAS_CONFIG.apiUrl al endpoint público /matriculas.


9. PUBLICAR EL BACKEND
----------------------

Crear o usar un repositorio de GitHub que contenga únicamente Backend-OEA.
No publicar la carpeta personal completa ni el archivo .env.

En Render o Railway crear un Web Service con:

  Build command:
    npm install && npx prisma generate && npm run build

  Start command:
    npm run start

Variables de entorno:

  DATABASE_URL
  DIRECT_URL
  CORS_ORIGINS
  ADMIN_API_KEY
  PORT (el proveedor normalmente lo proporciona automáticamente)

Después del despliegue probar:

  GET https://DOMINIO-PUBLICO/events

Actualizar el frontend con ese dominio y volver a probar Eventos y
Matriculación desde el sitio publicado.
